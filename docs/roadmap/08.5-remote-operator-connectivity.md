# 08.5 - Kiln Connect Remote Connectivity

Status: Ready
Priority: Urgent
Execution: Ready - close the existing listener guardrail, then admit a
bring-your-own private transport behind the Roadmap 08 session boundary.
Created: 2026-08-14

## Objective

Make a Kiln GUI running on an operator-owned development machine reachable
from a phone, tablet, or browser through `kiln connect`, while execution,
filesystem access, provider credentials, tools, approvals, and project state
remain on that machine.

Deliver useful remote operation without building or requiring a Kiln-hosted
cloud. Preserve a transport boundary that can later admit an optional managed
relay without rewriting operator identity or Runtime authority.

## Ownership

This track owns remote endpoint configuration and evidence, connector/tunnel
adapters, loopback origin binding, reachability health, background lifecycle,
reconnection, version compatibility, and connect/disconnect recovery.

Roadmap 08 owns pairing, device identity, operator sessions, scopes, expiry,
and revocation. Operator Runtime owns execution authority. GUI, CLI, TUI, and
future mobile/native surfaces render shared status and never own connection or
session truth.

Transport adapters may prove that traffic arrived through an admitted path;
they cannot authenticate the Kiln operator, mint a Runtime session, widen a
scope, approve an action, select a provider credential, or dispatch work.

## Scope

- Explicit loopback-only binding for the local GUI/runtime origin.
- An operator-supplied HTTPS/WSS endpoint mapped to that loopback origin.
- Initial adapters/evidence for private-network, Cloudflare Tunnel, and
  self-hosted reverse-proxy deployments, chosen from verified capabilities.
- A single connector interface for start, stop, status, endpoint, health,
  diagnostics, and recovery without pretending transports are equivalent.
- A headless/background lifecycle that survives closing the local or remote
  browser and can be disabled exactly.
- Reconnection that reattaches a replaceable surface to canonical Runtime
  work without duplicating or cancelling it.
- Responsive web-GUI validation on a real narrow viewport before any native
  mobile application is considered.
- Version/capability evidence so an incompatible client or connector fails
  explicitly.

## Initial Deployment Contract

The first release is bring-your-own connectivity:

```text
phone browser
  -> operator-owned HTTPS/WSS endpoint
  -> admitted transport connector
  -> 127.0.0.1 Kiln GUI/Operator boundary
  -> Operator Runtime
  -> Codex / Claude / OpenCode / direct adapters
```

Kiln owns the application session and Runtime authority at the inner boundary.
The operator owns the transport account, hostname, policy, and availability.
The origin never binds publicly merely because Connect is enabled.

## Non-Goals

- No Kiln-hosted relay, account database, tunnel allocation, DNS zone,
  notification service, bandwidth subsidy, billing, or multi-tenant control
  plane.
- No automatic Cloudflare, Tailscale, or other vendor account provisioning.
- No public unauthenticated URL, quick-tunnel fallback, router port-forward,
  UPnP, or listener on all interfaces.
- No direct exposure of Codex, Claude Code, OpenCode, Model Gateway, MCP, shell,
  terminal, or provider credentials.
- No transport header or network membership treated as sufficient operator
  authorization.
- No native mobile application in the initial track.
- No promise that every transport supports the same identity, source address,
  WebSocket lifetime, recovery, or revocation semantics.

## Research Basis

The active evidence synthesis is
[Remote Operator Connection Research](../research/active/43-remote-operator-connection-2026.md).

Current evidence supports three reference families:

- Anthropic Claude Code and OpenAI Codex keep execution local and use
  outbound connections to a hosted relay; remote clients are projections of
  local state.
- VS Code Remote Tunnels similarly separates a local server, authenticated
  outbound tunnel, remote client, and service lifecycle.
- T3 Code supports both operator-owned direct/private endpoints and T3
  Connect's managed Cloudflare path, while keeping the environment server as
  the access-token authority.

Cloudflare Tunnel and private mesh transports both avoid inbound firewall
ports, but differ in account ownership, client requirements, identity,
WebSocket behavior, and public reachability. They are adapters, not one
generic security promise.

## Current Repository Evidence

The existing GUI is already web-first and has narrow-viewport behavior, but it
is not a safe remote boundary:

- `startGuiGateway` does not explicitly set a hostname; the admitted fix is an
  exact `127.0.0.1` binding.
- GUI HTTP routes currently use wildcard CORS.
- GUI WebSocket identity currently accepts a client-provided anonymous
  `userId`.
- Operator terminal capability is a separate high-authority path and must not
  enter the initial remote scope.
- The persistent Operator Runtime already demonstrates authenticated loopback,
  exact-instance lifecycle, bounded credentials, and fail-closed binding; its
  internal credentials are evidence to reuse conceptually, not remote browser
  tokens to expose.

## Ordered Slices

### Slice 0 - Loopback And Exposure Guardrail

Status: Ready; independently admissible safety work.

Bind the GUI gateway explicitly to `127.0.0.1`, replace wildcard CORS with an
exact local-origin policy, and add tests proving that normal GUI startup never
creates a LAN/public listener. Inventory every GUI HTTP/WebSocket route and
classify its required future scope before Roadmap 08 integrates authentication.

Exit gate: local GUI works; direct non-loopback access is rejected or
unreachable; no remote-mode flag can widen the listener; the route/scope map is
complete enough for Roadmap 08 Slice 3.

Recovery: the change narrows reachability only; rollback is unnecessary for an
unsupported public listener. Explicit development fixtures may inject a test
listener without changing the production default.

### Slice 1 - Bring-Your-Own Endpoint Contract

Status: Blocked on Roadmap 08 Slice 1.

Define typed desired intent and observed evidence for a remote endpoint:
transport kind, HTTPS/WSS origin, connector identity/version, ownership,
health, last transition, configuration provenance, and limitations. Validate
scheme, host, redirects, mixed content, origin equality, and loopback target.
Do not store connector tokens in shared config or status projections.

Exit gate: invalid, insecure, mismatched, or unproven endpoints fail closed;
status separates desired, configured, running, reachable, authenticated, and
degraded states.

Recovery: removing endpoint intent stops the connector and leaves local GUI,
project state, sessions, and provider configuration intact.

### Slice 2 - First Private Transport Adapter

Status: Blocked on Slice 1 and an explicit operator choice of transport.

Implement one operator-owned transport adapter selected from current evidence.
The adapter must resolve an existing installation/configuration, point only to
the loopback origin, expose exact lifecycle/status evidence, redact credentials,
and never install or mutate an external account without a separate authorized
operation.

The selection decision must compare at least:

- private-client requirement and phone usability;
- HTTPS/WSS and long-lived connection behavior;
- external identity and policy ownership;
- Windows background-service support;
- endpoint stability and reconnect semantics;
- revocation, diagnostics, portability, and vendor exit.

Exit gate: a synthetic connector fixture and one operator-authorized live path
prove enable, reconnect, disable, and exact cleanup. No fallback opens a public
listener or unauthenticated endpoint.

Recovery: stop only the connector instance Kiln started or adopted explicitly;
foreign services and external account configuration remain untouched.

### Slice 3 - Persistent Connect Service

Status: Blocked on Slice 2 and Roadmap 08 Slice 3.

Run the local Connect host under one current-user, exact-instance supervisor.
Closing a GUI window or losing a phone connection detaches the surface without
cancelling the active turn. Start, ensure, stop, restart, status, doctor, and
uninstall act only on state carrying Kiln ownership and identity evidence.

Exit gate: reboot/logon recovery, stale-state recovery, graceful shutdown,
foreign-process refusal, connector teardown, and active-turn detachment pass
focused tests. No secret appears in process arguments, task definitions, logs,
or status JSON.

Recovery: disable remote ingress, revoke remote sessions, stop the exact
connector, and leave canonical Runtime/economic/project state untouched.

### Slice 4 - Mobile Web And Reconnection Proof

Status: Blocked on Slice 3.

Validate the bundled responsive GUI over the admitted HTTPS/WSS endpoint on a
narrow touch viewport. Cover pair, session list, active transcript, composer,
approval, goal control, disconnect, reconnect, offline/degraded status, and
revocation. Defer terminal, provider auth, setup mutation, and arbitrary
workspace access.

Exit gate: remote/mobile behavior consumes the same Gateway contracts as local
GUI; reconnect observes the canonical active turn; duplicated dispatch and
surface-owned authority are absent; accessibility and coarse-pointer behavior
pass focused checks.

Recovery: mobile-specific presentation can be narrowed without changing the
session, transport, or Runtime contract.

### Slice 5 - Second Transport And Portability Proof

Status: Deferred until the first adapter is live validated.

Add a second materially different transport to prove that the connector
boundary is real rather than a renamed vendor wrapper. Promote shared behavior
only where both adapters provide evidence; keep vendor-specific limitations
explicit.

Exit gate: the same session and surface contracts operate through both
transports; switching does not duplicate identity or Runtime authority; exact
disable/cleanup is proven for each adapter.

### Slice 6 - Optional Managed Relay Decision

Status: Deferred; no implementation admitted by this roadmap.

Reassess whether operator demand, reliability, setup friction, privacy,
economics, notification requirements, and multi-device evidence justify a
Kiln-managed relay. A hosted service requires a separate ADR and roadmap with
explicit tenancy, abuse, retention, observability, incident, billing, data
residency, and exit responsibilities.

Exit gate: adopt, defer, or reject a managed relay from measured evidence. No
placeholder cloud package, schema, provider abstraction, or compatibility path
is created meanwhile.

## Dependencies

- Roadmap 08 owns the authenticated operator-session contract.
- Slice 0 is safety hardening and may land before the remaining Roadmap 08
  implementation.
- Slice 1 requires Roadmap 08's typed session identity so endpoint evidence
  cannot become authentication authority.
- Slice 3 should reuse the proven exact-instance lifecycle shape of Operator
  Runtime/Model Gateway where it fits, without merging their state ownership.
- Provider/harness adapters remain behind Operator Runtime and are not
  connectivity dependencies.

## Promotion Gates

- `Kiln Connect` is one product experience over separate session, transport,
  surface, and Runtime contracts.
- The origin remains loopback-only; connectors initiate outbound or
  operator-owned private connectivity.
- Every remote HTTP/WebSocket operation is authenticated and authorized by
  Roadmap 08 contracts.
- Transport compromise cannot by itself mint or widen a Runtime session.
- Disconnecting a surface does not cancel active work; explicit Runtime
  cancellation remains separate.
- Start/stop/revoke/disable and foreign-instance refusal are exact and
  recoverable.
- No Kiln-hosted cloud is required through Slice 5.
- A managed relay cannot enter through incremental scope creep; it requires a
  separate evidence-backed decision.

## Verification

Listener-binding tests, route/scope inventory, endpoint-schema tests,
connector lifecycle fixtures, secret-redaction tests, HTTP/WebSocket auth and
origin negatives, reconnect/duplicate-dispatch tests, exact-instance service
tests, responsive Playwright coverage, affected package tests/typecheck,
`git diff --check`, and documentation-link verification.

Live transport tests require explicit operator authority, external-account
availability, and cleanup evidence. Source tests do not constitute proof that
an external endpoint, mobile network, or background service works live.

## Completion Criteria

An operator can run `kiln connect`, reach the local Kiln GUI from a phone
through an operator-owned secure transport, pair and revoke devices through
Roadmap 08, supervise and steer canonical Runtime work, survive browser/network
disconnects, and disable the connection exactly. Provider credentials,
filesystem authority, execution, approvals, and project state remain on the
development machine. The result requires no Kiln-hosted cloud and leaves a
proven boundary for an optional later relay decision.
