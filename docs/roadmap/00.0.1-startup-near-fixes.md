# 0.0.1 - Startup Near Fixes

## Status

Proposed. Created on 2026-05-17.

This track reduces operator-surface startup latency without changing runtime
semantics, provider authority, managed-agent policy, or native cockpit scope.

## Objective

Make CLI, GUI, and TUI startup feel immediate by removing external
provider/model discovery from the first usable surface path.

## Evidence

Local measurements on 2026-05-17 showed:

| Path | Mean wall time | Finding |
| --- | ---: | --- |
| CLI version command | 319ms | Process startup is acceptable. |
| CLI module import | 272ms | Module load is acceptable. |
| GUI provider-model module import | 279ms | Import cost is not the issue. |
| Managed-agent provider model discovery | 3547ms | Major pre-surface blocker. |
| Codex CLI model discovery | 1051ms | Significant external discovery cost. |
| OpenCode CLI model discovery | 2712ms | Dominant external discovery cost. |
| Operator discovery with Codex/OpenCode | 3500ms | Matches perceived delay. |
| Operator discovery with no providers | 3543ms | Empty availability still probes external CLIs. |
| GUI prod no-open startup to banner | 4376ms | User-visible startup is dominated by pre-gateway setup. |

Existing runtime tests already prove GUI/TUI gateways can listen before provider
discovery finishes:

- `packages/runtime/tests/gateway/gui-gateway.test.ts`
- `packages/runtime/tests/gateway/tui-gateway-clear.test.ts`

The remaining issue is CLI command startup doing managed-agent/provider
discovery before the operator surface is usable.

## Scope

- Defer managed-agent provider model discovery until after GUI/TUI surface
  startup.
- Start operator surfaces with managed-agent status `pending` when discovery is
  unresolved.
- Refresh provider and model discovery in the background using the existing
  provider-catalog service pattern.
- Add cached provider discovery records with source, timestamp, TTL, executable
  path, model list, and last error.
- Prevent empty provider availability from probing Codex/OpenCode CLIs.
- Preserve fail-closed behavior when a managed-agent invocation is requested
  before route evidence is available.

## Non-Goals

- No Rust, WASM, sidecar, or native-kernel implementation.
- No provider-routing rewrite.
- No authority, permission, or managed-agent policy change.
- No private GUI/TUI provider truth.
- No benchmark-only startup behavior.

## Slices

### Slice 1 - Discovery Admission Guard

Change operator provider discovery so unavailable providers do not start
external CLI probes.

Expected files:

- `packages/runtime/src/gateway/gui-provider-models.ts`
- `packages/runtime/tests/gateway/gui-gateway.test.ts`
- `packages/runtime/tests/gateway/tui-gateway-clear.test.ts`

Verification:

- Empty availability does not call Codex/OpenCode discovery.
- Available Codex/OpenCode still discover normally.
- Runtime gateway non-blocking discovery tests remain green.

### Slice 2 - CLI Surface Staged Startup

Move managed-agent provider model discovery out of the GUI/TUI pre-gateway
critical path.

Expected files:

- `packages/cli/src/commands/gui.ts`
- `packages/cli/src/commands/tui.ts`
- `packages/cli/src/config/managed-agent-provider-models.ts`
- relevant `packages/cli/tests/commands/*` startup tests

Verification:

- GUI command reaches gateway/banner before managed-agent provider discovery
  resolves.
- TUI command reaches renderer startup before managed-agent provider discovery
  resolves.
- Managed invocation remains unavailable or pending until route evidence is
  resolved.

### Slice 3 - Provider Discovery Cache

Persist bounded discovery results so startup can show stale-labelled provider
state while background refresh runs.

Expected files:

- runtime provider discovery cache/service modules
- CLI config or application support modules
- GUI/TUI provider-status tests

Verification:

- Cached entries include source, timestamp, TTL, executable path, models, and
  last error.
- Expired entries never become authoritative route evidence.
- Background refresh replaces stale startup data.

## Acceptance Criteria

- `kiln gui --prod --no-open` reaches startup banner without waiting for
  Codex/OpenCode model discovery.
- GUI and TUI surface startup does not block on managed-agent route model
  discovery.
- Provider discovery remains visible, refreshable, and fail-closed for actual
  execution.
- No surface owns provider/model truth outside shared contracts.
- Focused tests and relevant typechecks pass.
