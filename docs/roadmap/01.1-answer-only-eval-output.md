# 01.1 - Answer-Only Eval Output

## Status

Active. Added on 2026-05-21.

Related roadmap:

- `docs/roadmap/01-background-parallel-agent-surface.md`

## Problem

`kiln run` currently writes the assistant answer and Kiln session telemetry to
the same standard output stream. This is useful for human operators, but it
breaks exact-format and machine-graded evaluations.

Observed during a Codex CLI vs Kiln CLI comparison on 2026-05-21:

- Codex CLI returned only the assistant answer.
- Kiln CLI returned the assistant answer followed by session metadata such as
  phase, cost, duration, context, and score.
- Exact-format prompts that require "only four bullets" or "one sentence" can
  pass at the assistant-content level while failing if the raw Kiln `stdout` is
  graded directly.

This weakens Kiln's benchmark harness story because evaluators must either
strip operator telemetry manually or risk measuring the wrapper output instead
of the model/system answer.

## Objective

Provide a governed answer-only output path for CLI and benchmark use while
preserving rich operator telemetry for normal interactive use.

Kiln should make the answer, telemetry, lifecycle evidence, and diagnostics
separable by contract, not by ad hoc log parsing.

## Scope

- Add a CLI output mode for answer-only responses.
- Add a structured output mode suitable for benchmark harnesses.
- Keep current human-readable session telemetry available for operator use.
- Ensure exact-format evals can grade only assistant content.
- Ensure telemetry remains available through a separate stream, file, event, or
  structured envelope.
- Document which mode benchmark runners must use.

## Non-Goals

- No removal of operator session summaries from the default interactive
  experience.
- No benchmark-specific prompt path.
- No hidden suppression of lifecycle evidence.
- No public benchmark claim based only on output cleanup.
- No changes to model/provider routing semantics.

## Proposed Contract

`kiln run` should support at least one of these stable modes:

- `--output answer`: write only assistant content to `stdout`.
- `--output json`: write a structured envelope with distinct `answer`,
  `telemetry`, `diagnostics`, and `resources` fields.
- `--telemetry-file <path>`: write operator/session telemetry separately while
  keeping `stdout` clean.

Exact flag names may change during implementation, but the contract must make
answer extraction deterministic.

## Slices

### Slice 1 - Output Mode Contract

Status: next.

Deliverables:

- Define CLI output modes for default human output, answer-only output, and
  structured output.
- Define how errors, diagnostics, and partial outputs are represented.
- Ensure answer-only mode never appends session summaries to `stdout`.

Expected files:

- `packages/cli/src/*`
- `packages/runtime/src/*`, only if runtime envelopes must change
- `packages/cli/tests/*`
- `docs/guides/eval.md`
- this roadmap

### Slice 2 - Benchmark Harness Integration

Status: pending.

Deliverables:

- Update benchmark/eval runners to use answer-only or structured output.
- Add regression tests for exact-format prompts.
- Document the required invocation pattern for Kiln-vs-native CLI comparisons.

## Acceptance Criteria

- A prompt requiring exact output can be run through Kiln and graded from raw
  `stdout` without stripping telemetry when answer-only mode is selected.
- Default operator mode still shows session telemetry.
- Structured mode exposes answer and telemetry as separate fields.
- Tests cover success, failure, timeout, and partial-output cases.
