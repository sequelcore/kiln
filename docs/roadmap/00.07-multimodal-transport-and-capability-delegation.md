# 00.07 - Multimodal Transport and Capability Delegation

Status: deferred foundation track

## Objective

Make multimodal work a governed Kiln control-plane capability across surfaces,
providers, models, tools, managed agents, and replay. Kiln should preserve
operator intent and evidence for images, documents, audio, and future
modalities without relying on ad hoc OCR or provider-specific behavior.

## Thesis

Kiln does not "analyze images" as a surface trick. Kiln transports multimodal
intent, artifacts, capability requirements, policy decisions, and degradation
evidence through a canonical runtime contract. The active model, an auxiliary
managed agent, or a transform such as OCR should be selected by explicit
capability routing.

Preferred execution order:

1. Use native model support when the active provider/model accepts the required
   modality.
2. Delegate to a managed auxiliary agent whose provider/model advertises the
   required capability.
3. Apply a governed transform such as OCR, thumbnailing, transcription, or
   document extraction.
4. Fail fast with a clear unsupported-modality reason when no governed route is
   available.

## Current Baseline

Kiln already has `ContentPart` types for image, audio, and file content, and
some provider adapters serialize image parts natively. The current runtime
path is not yet end-to-end multimodal:

- `view_image` can return model-consumable image content.
- Runtime tool projection currently collapses most tool results into string
  output for the next provider turn.
- Resource-link projection is preserved, but binary image content from tool
  results is not consistently propagated as model-visible content.
- OCR exists as a tool, but should be an explicit transform rather than the
  default fallback for "analyze this image".
- Provider discovery has early vision metadata, but routing does not yet use a
  full modality-capability matrix.

## Required Foundation

- Define a canonical multimodal artifact contract for local files, uploaded
  files, webhook attachments, generated screenshots, tool outputs, and managed
  child artifacts.
- Store multimodal inputs and outputs in the resource plane using stable
  artifact URIs, metadata, checksums, MIME type, dimensions or duration, source
  provenance, retention policy, and replay references.
- Extend tool-result and session-history contracts so model-visible
  multimodal parts can survive `surface -> runtime -> tool -> session history
  -> provider adapter`.
- Require provider adapters to declare modality support and serialization
  constraints, including base64 versus URL support, size limits, document
  support, tool-result multimodality, and known degradation behavior.
- Build a modality planner that selects native, delegated, transformed, or
  failed execution with auditable reasons.
- Treat OCR, image downsampling, document extraction, and transcription as
  governed transforms with explicit outputs and sidecar artifacts.

## Capability Delegation

When the active provider/model cannot accept the required modality, Kiln may
route a bounded subtask to an auxiliary managed agent with the required
capability. This is capability delegation, not silent fallback.

The delegation contract must record:

- artifact URI and artifact metadata sent to the auxiliary route
- requested capability, such as `vision`, `document`, `audio`, or
  `screenshot-review`
- selected provider, model, agent profile, and route-health evidence
- authority level, tenant/project policy, and cost budget decision
- structured result returned to the parent agent
- uncertainty, limitations, and transform provenance when applicable

Candidate auxiliary profiles:

- `vision-describer` for general image analysis
- `ui-screenshot-reviewer` for screenshots and UI findings
- `diagram-reader` for architecture and workflow diagrams
- `document-ocr-reviewer` for image-heavy documents and forms
- `visual-regression-agent` for screenshot comparison

## Cross-Surface Requirements

CLI, TUI, GUI, webhooks, SDK, and managed agents must share the same artifact
and modality semantics. Surface differences should only affect presentation.

- GUI can render thumbnails, previews, galleries, and compare views.
- TUI and CLI can render numbered resource links, metadata, and concise text
  fallbacks.
- Webhook attachments should normalize into the same artifact contract as local
  files and GUI uploads.
- Replay should not depend on the original local file path or external URL when
  Kiln captured the artifact under governed retention.
- Transcript events should show when native, delegated, transformed, or failed
  multimodal routing occurred.

## Cross-Provider Requirements

Provider adapters must not silently discard modalities. Each adapter should
either serialize the modality faithfully, request delegated handling, invoke a
governed transform, or fail closed.

The capability model should cover:

- accepted input modalities
- accepted output modalities
- native tool-result multimodality
- image URL support
- base64 support
- file/document support
- maximum size and count per request
- downsample or compression policy
- model-specific modality caveats discovered at runtime

## Verification

This track is not complete until tests prove parity across the runtime and
operator surfaces:

- local image through CLI
- uploaded image through GUI
- image attachment through webhook
- screenshot artifact from browser tooling
- native vision route
- delegated vision route
- OCR transform route
- provider/model without vision support
- unavailable OCR backend
- large image downsample or rejection
- replay from persisted session using artifact references
- managed child returning multimodal evidence to a parent agent

## Completion Criteria

- Multimodal inputs and tool results survive end-to-end as governed content,
  not just string summaries.
- Native vision is preferred when supported and policy allows it.
- Auxiliary managed-agent delegation is available when native support is
  absent or not preferred.
- OCR and other transforms are explicit, auditable degradations.
- All surfaces present the same underlying routing and artifact evidence.
- Provider adapters fail closed instead of silently dropping unsupported
  modalities.

## ADR Trigger

Create an ADR before implementation starts if this track chooses permanent
contracts for artifact retention, provider modality capability schema,
tool-result multimodality, or managed-agent capability delegation semantics.
