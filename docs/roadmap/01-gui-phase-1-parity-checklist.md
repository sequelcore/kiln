## How to use
- Each row is a discrete capability currently provided by `@kilnai/tui`.
- The GUI reaches parity when every row is ✅ in a production build (`@kilnai/gui` shipped to users, not a dev harness).
- Rows marked `(out of scope)` were considered and deferred — they do not block deletion.
- A capability in the TUI not listed here is a gap in this checklist, not a reason to keep the TUI. File a PR against this document.
- Parity is verified by: (a) a manual walkthrough checklist run by Ricardo, and (b) at least one automated e2e test per category exercising the pass criterion.

## Out of scope (deferred — do NOT block deletion)

Each item below was examined and consciously not required for parity. Reconsidering any of these should produce a new ADR, not a TUI stay of execution.

- **9 of 12 terminal-tuned color themes.** See 5.1a. Port community themes post-deletion if user demand warrants.
- **Vim-style `j`/`k` navigation (4.7).** Arrow keys alone satisfy parity. Can be added as a muscle-memory affordance post-parity.
- **Direct transport (`KILN_TUI_TRANSPORT=direct`) (6.7).** ADR-006 commits GUI Phase 1 to gateway-only; direct in-process transport is a CLI-specific debugging affordance with no GUI analogue.
- **Placeholder-disabled auto-scroll yank (visible in `ui.ts`: `placeholder: ""`).** Placeholder microcopy is a polish item, not a capability.
- **Ctrl+V as the sole paste mechanism (4.2).** GUI uses platform standard paste; the underlying clipboard read does not need to replicate the TUI's subprocess-based approach (OS webview handles it).
- **TUI's 2s field poll as a hard cap (3.4).** Parity requires ≤ 2s; GUI may use push if the runtime supports it. Equivalence, not identity.
- **Printable-first key routing** (TUI quirk where keys are appended before special-case handlers run). GUI uses standard input field focus model; no equivalent mechanism needed.
- **Terminal-width responsive collapse at exactly 100 columns (5.6).** GUI picks its own threshold appropriate to the window metaphor.
