Slice 4 is complete as the Codex live proof and current Codex CLI event

This roadmap follows `01` and `01.5`. It does not reopen managed invocation or
write-authority doctrine. It proves the completed contracts against live
adapter behavior before Kiln expands into multi-child, conductor, scheduling,
or durable workflow roadmaps.

## Goal

Turn the deterministic `01.5` write-authority proof into live adapter confidence.

The target is not "trust the provider." The target is: live provider and
harness output must be captured, reduced, denied, or accepted through Kiln's
existing managed invocation and write-authority boundary.

## Non-Goals

- Do not add fan-out, fan-in, conductor planning, nested teams, or schedulers.
- Do not make live provider calls part of normal `bun run test`.
- Do not grant unbounded workspace write access for convenience.
- Do not let Codex, OpenCode, Claude Code, Hermes, or OpenClaw vocabulary become
  the Kiln contract.
- Do not require external credentials for deterministic unit tests.
- Do not inline raw diffs or transcripts into canonical session events.

## First Scout Findings

Kiln already has the right internal event shape:

- `packages/runtime/src/execution/cli-session-contract.ts` defines
  `CliSessionEvent.file_changed` with path, change type, line counts, diff
  preview, and truncation metadata.
- `packages/cli/src/wrapper/session.ts` mirrors the same live wrapper event
  shape.
- `packages/cli/src/wrapper/provider-session.ts` can emit `file_changed` from
  direct provider tool results.
- `packages/cli/src/wrapper/codex-session.ts`,
  `packages/cli/src/wrapper/opencode-session.ts`, and
  `packages/cli/src/wrapper/claude-code-process.ts` currently expose text,
  tool, cost, and terminal events, but need live write/diff evidence mapped
  explicitly.
- GUI and TUI activity streamers already understand `file_changed` events and
  approval transitions, so the live hardening path can reuse existing operator
  projection primitives.

OpenCode current local clone exposes:

- `permission.asked` / `permission.reply`
- edit permission collapsed across `edit`, `write`, and `apply_patch`
- session diff storage and `session.diff`
- file diff summaries through `Session.Event.Diff`
- HTTP API routes for permission response and session diff retrieval

Codex current local clone exposes:

- apply-patch parsing and verification
- patch approval request/response paths
- turn diff tracking for apply-patch and shell-heredoc apply-patch
- app-server protocol notifications for file-change patch updates and output
  deltas
- permission profile, sandbox policy, approval policy, and managed permission
  concepts

Hermes and OpenClaw remain secondary targets for this roadmap. They were pulled
because they may inform later compatibility checks, but the first live proof
should use the adapter with the clearest file-change and permission evidence.

## Safety Rules

Live tests must be opt-in.

Required live-test constraints:

- require an explicit environment variable such as
  `KILN_LIVE_MANAGED_AGENT_TESTS=1`
- write only inside a dedicated fixture directory
- create a fresh temporary child workspace or reset the fixture file before and
  after the test
- run with network disabled when testing local harness behavior
- use read-only authority for the denial proof
- use approved-write authority only for the positive proof
- fail if any file outside the admitted allowlist changes
- store raw diffs behind artifact/resource URIs, not inline session events
- preserve session replay after reload

### Slice 3: OpenCode Live Proof

Status: completed on 2026-05-05.

OpenCode is the first practical target because the current clone exposes
permission, diff, edit/write/apply-patch, and session diff concepts in one
runtime.

Completed work:

- mapped OpenCode `session.diff` events into provider-neutral
  `CliSessionEvent.file_changed` events without inlining raw diffs
- mapped OpenCode write-tool permission failures into provider-neutral
  `write_decision` denial events
- extended the managed CLI harness adapter to collect live write-decision
  evidence alongside live file-change evidence
- added a filesystem boundary for live harnesses that snapshots tracked files,
  detects silent writes, optionally restores read-only violations, and emits
  canonical `write-authority-denied` evidence
- added an opt-in OpenCode live proof guarded by both
  `KILN_LIVE_MANAGED_AGENT_TESTS=1` and `KILN_LIVE_OPENCODE_TESTS=1`
- verified that approved OpenCode writes produce proposal, approval, attempt,
  terminal, and replay evidence through the Kiln contract

Live finding:

- OpenCode `1.14.33` with provider model `opencode/minimax-m2.5-free` can still
  modify the fixture file during a read-only Kiln invocation even when the
  native OpenCode permission configuration is set to deny. Kiln therefore must
  not rely on provider-native permission behavior alone. The adapter boundary
  now detects the retained write, restores the tracked file, and records the
  denial as Kiln write-authority evidence.

Proof cases:

- read-only managed invocation cannot retain an accepted write: met by the Kiln
  filesystem boundary, which restores the tracked file and records
  `write-authority-denied`
- approved-write managed invocation writes only the fixture allowlist path: met
- Kiln records proposal, decision, attempt, terminal evidence, and replay state:
  met
- no raw diff is inlined into session events: met

- Codex CLI `0.128.0` emits the current file-change contract as

  denied evidence.

- shell-heredoc apply-patch is either intercepted safely or denied: met through

Admission rules for future provider support:

- A provider is not "live-proven" until both read-only denial and approved-write
  fixture proofs pass through managed invocation.
- Provider-native permission, sandbox, or workspace claims are advisory until
  Kiln observes the filesystem result and canonical session evidence.
- Raw provider diffs and transcripts remain artifacts or resources; session
  events carry bounded summaries and stable references.
- Provider child-agent names such as `subagent`, `delegate_task`,
  `sessions_spawn`, or ACP runtime labels cannot become Kiln contract fields.
- Future adapters must pass the same checklist: event extraction, authority
  mapping, boundary observation, denial evidence, replay serialization, and
  opt-in live tests.
