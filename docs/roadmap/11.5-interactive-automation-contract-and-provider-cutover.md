# 11.5 - Interactive Automation Contract And Provider Cutover

Status: Queued
Priority: High
Execution: Queued behind Roadmap 11 Slice 6. After that artifact-continuity
boundary closes, this track takes precedence over Roadmap 11 Slices 7 and 8.
Created: 2026-09-04

## Objective

Make Kiln's first-party browser and desktop automation honest, bounded, and
independently useful through Runtime's existing agent loop. Kiln owns intent,
capability admission, authority, action sequencing, evidence, recovery, and
completion. A selected automation provider owns only physical interaction with
the admitted target.

The completed path must work without Codex, Claude Code, OpenCode, or another
external harness installed:

```text
operator request
  -> bounded work and required capability
  -> admitted provider and environment
  -> authorized action
  -> target-bound post-action evidence
  -> verification
  -> canonical completion or retained uncertainty
```

External harness computer-use systems remain optional whole-task execution
routes. They never become hidden implementations of Kiln's atomic browser or
desktop actions.

## Priority Decision

This track does not precede Capability Fabric. Roadmap 11 owns the canonical,
provider-neutral capability catalog, eligibility decisions, exact schemas, and
portable invocation identity that interactive automation must reuse. Roadmap 11
Slice 6 also closes artifact identity and access across agent-backed execution,
which browser and desktop evidence need rather than reimplement.

This track also does not wait for all of Capability Fabric. Roadmap 11 Slices 7
and 8 expand cross-surface and cross-harness promotion. Continuing that
expansion while first-party interactive automation advertises unsupported
operations and carries overlapping provider infrastructure would deepen the
wrong dependency. The admitted order is therefore:

```text
Roadmap 11 Slices 0-6
  -> Roadmap 11.5
  -> Roadmap 11 Slices 7-8
```

This is a product-priority boundary, not a transfer of ownership. Capability
Fabric remains canonical while Roadmap 11.5 owns interactive automation
execution contracts, provider conformance, and provider cutover.

## Ownership

Core owns the provider-neutral `BrowserAutomationPort` and
`DesktopAutomationPort`, browser and desktop action types, result schemas,
effect declarations, capability contributions, and pure eligibility inputs.
It does not import Playwright, Cua, native operating-system helpers, Runtime,
CLI, or operator surfaces.

Runtime owns the concrete adapters behind those ports, live automation
sessions, provider invocation, cancellation, observation collection, artifact
handoff, and conservative settlement. The existing Execution Kernel remains
the owner of irreversible Kiln dispatch fencing; this track does not create
another kernel, orchestrator, or retry authority.

Capability Fabric owns canonical capability identity, current eligibility,
descriptor digests, implementation selection evidence, and model-facing
materialization. Provider observations feed that owner; they do not form a
second capability catalog.

Configuration owns provider and environment intent. CLI composition resolves
that intent into exact Runtime adapters and diagnostics. GUI, TUI, SDK, CLI,
and native harness surfaces render shared evidence and never select a provider,
infer support, or settle an action.

The context resource plane owns screenshots, traces, accessibility or DOM
snapshots, console/network records, downloads, and other retained artifacts.
Interactive providers return artifact material or references but do not create
an alternate resource authority.

## Target Architecture

```text
Kiln Operator Workspace / Gateway
  -> Work Governance and RuntimeSessionOrchestrator
  -> Capability Fabric admission
  -> Execution Kernel for consequential dispatch
  -> Interactive Automation Runtime
       -> BrowserAutomationPort
            -> direct Playwright adapter
            -> isolated browser context
       -> DesktopAutomationPort
            -> admitted Cua Driver adapter candidate
            -> isolated desktop environment by default
            -> local desktop only by explicit operator admission
  -> context resource plane
  -> verification and canonical completion

Optional whole-task route
  -> existing Agent Task / managed-invocation lifecycle
  -> Codex, Claude, or another admitted external harness
  -> returned evidence and Kiln acceptance decision
```

The internal ports may group lifecycle methods around a closed action union,
but that shape does not dictate the model-facing catalog. Initial delivery
retains atomic model-facing operations and materializes only the operations
supported by the admitted provider. A later consolidation into broad
`browser_act` or `desktop_act` tools requires measured context or selection
benefit without weakening effect, approval, or evidence precision.

## Current Repository Evidence

- `InteractiveUseProvider.execute(request)` currently accepts browser and
  desktop requests through one broad contract.
- The default builtin surface constructs every browser and computer tool even
  when no provider or only a capability-reduced provider is configured.
- `browser_observe` advertises screenshot, DOM, accessibility, console, and
  network observations. The current Playwright provider returns URL, title,
  visible body text, and an optional screenshot.
- `browser_click` advertises provider refs, selectors, and coordinates. The
  current Playwright provider dispatches selectors or coordinates and rejects a
  ref-only request during execution.
- The Nut.js provider implements coordinate input but rejects application
  lifecycle operations. The Windows UIA provider implements semantic and
  application lifecycle operations but rejects coordinate input and raw
  keypresses. Those differences are discovered after model-facing tool
  construction.
- Playwright already runs directly inside Kiln's Bun Runtime. This track
  hardens and narrows that implementation; it does not migrate from MCP or a
  CLI text protocol.
- Browser capture, custom video rendering, editor export, Windows capture,
  Nut.js, and Kiln-owned UIA infrastructure currently share the interactive
  execution area despite having different product and evidence responsibilities.
- The repository has no supported installable package line or demonstrated
  external consumer requiring a compatibility period.

## Scope

- Truthful pre-dispatch capability exposure for browser and desktop operations.
- Separate TypeScript-owned `BrowserAutomationPort` and
  `DesktopAutomationPort` contracts.
- Immutable, version-bound provider observations normalized into Capability
  Fabric contributions.
- Provider-neutral action, observation, refusal, cancellation, and settlement
  contracts with bounded outputs.
- Model-free browser and desktop conformance fixtures with target-owned oracles.
- A thin direct Playwright browser adapter with semantic targeting, bounded
  snapshots, requested inspection channels, native artifacts, and exact
  post-action observations.
- Evaluation of Cua Driver as the preferred desktop candidate, including its
  direct TypeScript SDK and private MCP/stdio integration surfaces.
- Evaluation of Cua Sandbox as the first isolated desktop-environment
  candidate. Local active-desktop execution remains an explicit, narrower
  operator choice rather than a fallback.
- Direct configuration, schema, provider, test, documentation, and dependency
  cutover after replacements pass their gates.
- Fixed-agent quality and safety comparison before provider promotion.
- Optional whole-task computer-use routing through existing Agent Task and
  managed-invocation owners after the first-party path is complete.

## Non-Goals

- No new `kiln-harness`, second Runtime loop, nested browser agent, nested Cua
  Agent, or alternate work lifecycle.
- No attempt to authorize or replay the private clicks, retries, provider calls,
  tools, subagents, or scheduling inside an external harness.
- No Playwright MCP embedding, Playwright CLI output parsing, Browser Use agent,
  Stagehand agent mode, or another private planning loop beneath an atomic Kiln
  tool.
- No assumption that providers are interchangeable. Provider-neutral contracts
  preserve capability-specific evidence and refusals.
- No dynamic fallback from one browser or desktop provider to another after
  admission or dispatch.
- No compatibility aliases, dual provider selection, deprecated readers, or
  retained legacy backend after a contract cutover.
- No custom video production, captioning, editor-project export, or showcase
  workflow inside an automation provider. A separately admitted product
  capability may consume native evidence artifacts later.
- No provider selection based on GitHub popularity, vendor-owned leaderboard
  position, or a successful provider response without an external state oracle.
- No broad model-facing `browser_act` or `desktop_act` consolidation without a
  benchmark proving a material benefit and no loss of governance precision.
- No cloud desktop account, credential, spend, or live local-desktop action
  authorized by this roadmap document.

## Ordered Slices

### Slice 0 - Containment And Truthful Exposure

Status: Blocked on Roadmap 11 Slice 6.

Freeze new interactive actions, operating-system backends, recorder/showcase
features, and compatibility layers. Characterize the current browser and
desktop behavior, then make required-but-unavailable observations and actions
fail before provider dispatch with typed capability evidence.

The builtin catalog must stop presenting every interactive operation merely
because one provider is configured. A request for DOM, accessibility, console,
network, semantic refs, application lifecycle, coordinate input, or raw
keypresses is executable only when current provider evidence supports that
exact operation. Missing required evidence cannot return a successful tool
result.

Exit gate: negative tests prove zero provider calls for unsupported operations;
configured and unconfigured catalogs expose only eligible operations; current
failures remain visible as bounded capability decisions rather than disappearing
or becoming provider errors.

Recovery: this slice narrows unsupported exposure and creates no external state.
If a legitimate current operation is omitted, correct its capability evidence;
do not restore eager exposure.

### Slice 1 - Browser And Desktop Port Cutover

Status: Blocked on Slice 0.

Replace `InteractiveUseProvider` outright with separate TypeScript-owned browser
and desktop execution ports. Define closed request, result, refusal,
cancellation, target identity, observation, and settlement contracts. Provider
observation DTOs remain inputs to Capability Fabric rather than canonical
catalogs of their own.

Update Core tool construction, Runtime composition, CLI configuration
resolution, public exports, tests, and affected gateway projections in the same
contract change. Do not retain an adapter that translates the old generic
interface into the new ports.

Exit gate: Core has no infrastructure imports; Runtime owns live session and
adapter invocation; browser and desktop requests cannot cross ports; affected
packages typecheck and focused contract tests pass with no legacy interface.

Recovery: roll forward within the same bounded contract change. The repository
has no external caller that justifies restoring the superseded interface.

### Slice 2 - Browser Provider Conformance

Status: Blocked on Slice 1.

Build deterministic local browser fixtures and provider-neutral tests before
expanding the Playwright adapter. Cover semantic selection, snapshot-bound refs,
stale-ref refusal, frames, popups, tabs, dialogs, shadow DOM, upload, download,
SPA navigation, console and network evidence, screenshots, traces, redirect
denial, cancellation, and post-action readback.

Every fixture uses page-owned state or another external oracle. A provider's
success response, trace entry, screenshot existence, or model claim is not by
itself proof that the intended state changed.

Exit gate: the suite detects intentional wrong-target, stale-ref, omitted
evidence, redirect, cancellation, and cleanup defects in a controlled mutant or
fixture. Observation sizes have explicit budgets and overflow behavior.

Recovery: fixtures and pure contracts create no browser dependency beyond the
existing optional Playwright development baseline. Unsupported cases remain
explicit until the adapter satisfies them.

### Slice 3 - Thin Playwright Adapter

Status: Blocked on Slice 2.

Refactor the existing direct Playwright implementation behind
`BrowserAutomationPort`. Add bounded ARIA or semantic snapshots, per-snapshot
refs, role/name targeting, explicit inspection for DOM, console, network,
trace, and page state, native screenshot/trace/download artifact registration,
and deterministic cancellation and cleanup.

Target selection uses snapshot-bound ref, role and accessible name, explicit
selector, then coordinates only when visual interaction is required. A stale
ref is rejected and never re-resolved heuristically. Redirect and current-URL
policy checks run after navigation and mutating actions before success is
reported.

Remove custom browser capture, rendered video, captions, and editor export from
the provider when equivalent native evidence exists or no current consumer
justifies the feature. Monitoring remains a bounded Runtime projection and does
not become a second browser-session owner.

Exit gate: browser conformance passes; Runtime and gateway lifecycle tests prove
one session owner and deterministic cleanup; GUI replay resolves artifact-backed
snapshots without owning browser control; no hidden model call occurs inside the
adapter.

Recovery: Playwright remains the only admitted browser provider. Failure leaves
the requested capability unavailable; it does not select another implementation
after admission.

### Slice 4 - Cua Integration Admission

Status: Blocked on Slice 1. Research and fixture work may proceed after the port
contract stabilizes without changing productive configuration.

Evaluate the exact current Cua Driver release through both supported embedding
candidates: the TypeScript SDK and a private MCP/stdio process. Compare Bun
compatibility, package and binary provenance, schema fidelity, process
lifecycle, cancellation, crash settlement, permission-mode ownership,
capability manifests, target binding, resource output, redaction, update
behavior, and operator setup.

Select one transport only when evidence demonstrates lower end-to-end
complexity while preserving exact authority, lifecycle, and settlement. MCP is
not preferred merely because it is runtime-neutral; the SDK is not preferred
merely because it is in-process.

Exit gate: record adopt, defer, or reject with exact version and fixture
evidence. A rejected or unavailable Cua candidate creates no placeholder
adapter, config value, dependency, or fallback path.

Recovery: the spike uses disposable fixtures and an explicitly bounded test
environment. It does not act on the operator's desktop, install a persistent
service, or create an external account without separate authority.

### Slice 5 - Desktop Provider Conformance

Status: Blocked on Slices 1 and 4 with an adopted Cua transport.

Build deterministic desktop fixtures for exact process/window binding,
wrong-window prevention, semantic invocation, text entry and readback, pixel
actions with before/after screenshots, foreground and background behavior,
focus and cursor preservation, DPI and multi-monitor behavior, child windows,
application lifecycle, cancellation, denied applications, and input-leakage
prevention.

Test local and isolated environments as distinct capability sets. Desktop-scope
pixel input never becomes window-bound authority, and window-less actions never
fall back to whichever application is active.

Exit gate: every admitted mutation has target-owned after-state evidence; every
unsupported combination is refused before input dispatch; no disallowed or
wrong-target action occurs in the deterministic fixtures; cancellation reaches
a deterministic terminal result or retains explicit uncertainty.

Recovery: conformance failures keep desktop automation unavailable. They do not
reactivate Nut.js or the Kiln UIA helper.

### Slice 6 - Isolated Desktop Environment

Status: Blocked on Slice 5 and an admitted environment implementation.

Evaluate Cua Sandbox as the first isolated multi-operating-system environment
candidate. Bind environment identity, image or snapshot identity, operating
system, provider version, lifecycle, network and filesystem posture, resource
limits, cleanup, and retained uncertainty into the Runtime execution binding.

Consequential desktop work defaults to an isolated environment. Local desktop
execution requires explicit operator selection, an exact application allowlist,
exact window identity, an operator-visible indicator, approval for credential
entry or other sensitive effects, post-action verification, and deterministic
cleanup. There is no fallback from isolated to local execution.

Exit gate: disposable environment creation, action, cancellation, teardown,
stale-instance refusal, retained-resource reporting, and policy denial pass
fixtures and one separately authorized live validation. Missing environment
evidence makes the capability unavailable.

Recovery: cleanup targets only the exact environment instance Kiln created or
adopted. Unknown remote settlement or retained resources remain visible and are
never reported as successful teardown.

### Slice 7 - Desktop Cutover And Legacy Removal

Status: Blocked on Slices 5 and 6.

Implement the admitted Cua Driver and environment adapters behind
`DesktopAutomationPort`, then replace productive configuration, diagnostics,
exports, tests, dependencies, build paths, and documentation in one cutover.

Delete the Nut.js provider, Windows UIA provider and native helper, Windows
capture infrastructure, old provider values, generic interactive schemas,
legacy readers, dual selection, active-window fallback, and tests whose only
purpose is preserving superseded implementation structure. If Cua or its
environment fails admission at runtime, desktop automation is unavailable.

Exit gate: repository search finds no productive legacy provider, config value,
dependency, helper, fallback, or documentation claim; desktop conformance and
cross-surface evidence projection pass; local durable configuration is either
migrated forward or discarded through an explicit operator-recorded decision.

Recovery: roll forward by correcting the new adapter or make desktop automation
unavailable. Do not restore a deleted backend as an automatic recovery path.

### Slice 8 - Whole-Task Routes And Comparative Promotion

Status: Blocked on the first-party browser and desktop verticals.

Represent Codex, Claude, or another harness-native computer-use system as a
bounded workload over existing Agent Task, managed-invocation, external-runtime
attachment, authority, economic, and settlement owners. Do not introduce a new
durable `ManagedComputerUseTask` lifecycle when the existing workload contract
can express the objective, target, limits, required evidence, and result.

Run a fixed-agent comparison with the exact model revision, prompt, Runtime
loop, context policy, tool schemas, environment, task fixtures, step/time/spend
limits, and evaluator held constant where the route permits. Whole-task routes
that do not expose atomic action evidence are evaluated at their actual
invocation boundary and never presented as exact Kiln action replay.

Exit gate: each route reports exact, partial/lossy, unsupported, or unknown
evidence without manufactured parity; Kiln accepts, rejects, or retains
uncertainty from canonical verification; provider promotion is non-inferior on
the declared fixed-agent task set and has no safety-gate violation.

Recovery: disabling a whole-task route leaves first-party Runtime automation
unchanged. Unknown external execution remains conservatively unsettled and
cannot trigger automatic redispatch.

## Dependencies

- Roadmap 11 Slice 6 must close artifact identity, access, digest, lineage,
  retention, and handoff before this track becomes the default work.
- Roadmap 11 Slices 7 and 8 wait on this track so cross-surface promotion does
  not amplify false or provider-specific interactive contracts.
- Capability Fabric remains the only capability catalog and eligibility owner.
- The context resource plane remains the only retained-artifact owner.
- RuntimeSessionOrchestrator remains the only first-party live model/tool loop
  owner.
- The Execution Kernel remains the owner of irreversible Kiln dispatch
  authorization and conservative observation.
- Existing Agent Task and managed-invocation contracts own optional whole-task
  routes. This track may add a workload profile but not a duplicate lifecycle.
- Live Cua Driver, Cua Sandbox, external account, local desktop, credential,
  installation, or spend validation requires separate operator authority.

## Promotion Gates

- Unsupported operations are absent or rejected before provider dispatch.
- Every mutation produces target-bound after-state evidence or an explicit
  unknown/partial settlement; provider success alone is insufficient.
- Provider version, environment identity, capability observation, and exact
  execution binding are persisted as secret-free evidence.
- Cancellation and cleanup terminate deterministically or retain explicit
  uncertainty and owned-resource identity.
- Browser and desktop observations remain within predefined context and
  artifact budgets.
- No hidden model call, nested agent loop, provider reselection, or silent
  fallback occurs inside an atomic automation provider.
- Deterministic fixtures produce no disallowed or wrong-target action.
- Replay contains no credentials, sensitive typed values, raw unbounded
  accessibility/DOM output, or operator-specific paths.
- Fixed-agent quality is non-inferior to the removed provider on the declared
  task set; popularity and vendor benchmark claims are not gates.
- Architecture and security review have no unresolved high- or medium-severity
  finding before local-desktop or consequential promotion.

## Verification

Verification begins with focused Core capability/tool tests, Runtime provider
and lifecycle tests, CLI configuration tests, gateway browser-session and
interactive-frame tests, and at least one GUI replay/projection test. Shared
contract changes then run affected package typechecks and tests together.

The model-free conformance suites use deterministic local fixtures and external
state oracles. The fixed-agent comparison is a separate benchmark lane and
cannot substitute for provider conformance or safety tests. Live provider and
environment tests are explicitly marked and excluded from hermetic default
suites.

Before each slice closes, run the smallest owning package gates plus
`git diff --check`. Run `bun run docs:check` whenever roadmap, architecture,
guide, or cross-reference content changes. The contract and provider cutovers
require `bun run typecheck` and the affected Core, Runtime, CLI, gateway-contract,
and operator-surface suites. The final candidate requires `bun run test` only
after focused failures are resolved and the same commit passed the narrower
gates.

## Completion Criteria

An operator can start a first-party Kiln session, request bounded browser or
desktop work, and receive only currently supported operations under an exact
provider and environment binding. Playwright performs browser interaction
through a thin Runtime adapter. An admitted Cua Driver implementation performs
desktop interaction in an isolated environment by default, with local desktop
use available only through explicit narrower authority. Every consequential
action returns target-bound evidence sufficient for Kiln to verify, reconcile,
and report completion or uncertainty.

The repository contains no generic `InteractiveUseProvider`, Nut.js backend,
Kiln-owned Windows UIA backend, custom provider-level media-production stack,
legacy provider configuration, or silent fallback. External harnesses remain
optional whole-task routes whose private loops and incomplete evidence are
represented honestly. Roadmap 11 Slices 7 and 8 may resume against these proven
first-party contracts.
