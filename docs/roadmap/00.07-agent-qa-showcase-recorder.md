# 00.07 - Agent QA Showcase Recorder

Status: active adjacent product track

This track follows the completed multimodal transport foundation documented in
`docs/architecture/multimodal-transport.md` and ADR-010. It depends on governed
artifact transport, capture evidence, and cross-surface replay, but it remains
a separate recorder product track and is not part of the late
live-browser/native sequence.

## Objective

Define and implement a governed recorder that turns Kiln agent runs into real
QA and showcase videos. The output should look like a polished screen recording
with cursor movement, clicks, typing, scroll, zooms, captions, and optional
voiceover. It must not be a slideshow of screenshots.

## Product Thesis

Traditional screen recorders capture pixels first and infer meaning later. Kiln
already owns the agent action timeline: tool calls, browser sessions, computer
actions, selectors, coordinates, URLs, window targets, timestamps, artifacts,
errors, and final outcomes. The recorder should combine real video capture with
that structured event evidence so Kiln can generate explainable, editable, and
replayable demos.

## Baseline Comparisons

Products such as Cursorful, Screen Studio, Pointerful, and DemoStudio focus on
screen recording polish: automatic cursor/click zooms, smooth pans, editable
zoom timelines, backgrounds, aspect-ratio exports, cursor emphasis, and
microphone/camera support.

Kiln should compete on those visible qualities, but its durable advantage is
that the recorder can be event-sourced from governed agent activity instead of
being only a pixel recorder.

## Recording Model

The recorder should produce a multi-track session artifact:

- Raw capture track: real browser or desktop video while the agent acts.
- Event track: tool calls, selectors, coordinates, clicks, typing, scroll,
  navigation, application/window targets, and timestamps.
- Artifact track: screenshots, DOM/accessibility snapshots, logs, resource
  links, and error evidence.
- Edit track: zoom keyframes, pan targets, captions, cuts, cursor emphasis,
  redactions, background, aspect ratio, and voiceover.
- Export track: MP4/WebM outputs plus a QA report and replay manifest.

Screenshots are evidence and fallback frames. They are not the primary video
format.

## Browser Capture

For governed `browser_*` sessions, prefer a browser-native capture path:

- Capture actual browser video from Playwright/CDP or the controlled browser
  context when available.
- Track cursor/click/selector events from browser tool metadata.
- Render automatic zooms from click positions or DOM target bounding boxes.
- Preserve URL/title/visible-text evidence for captions and QA reports.
- Keep raw video and derived exports in the resource plane with bounded
  retention.

## Computer Capture

For governed `computer_*` sessions, capture the active target window or desktop
region when policy allows:

- Record the actual app/window while actions occur.
- Correlate UI Automation/accessibility targets with click/type events.
- Support cursor highlight, keyboard overlays, and window/app captions.
- Redact sensitive typed input when tool metadata marks text as sensitive.
- Fail closed when capture permission, app authorization, or platform provider
  is unavailable.

## Auto-Edit Model

Kiln should render a first-pass edit automatically:

- Zoom on clicks, focused fields, changed UI regions, or selected DOM/UIA
  targets.
- Pan smoothly between action centers using bounded easing.
- Cut idle gaps and long waits while preserving failure context.
- Add optional captions from tool names, app/window titles, URLs, and
  agent-authored step summaries.
- Export common aspect ratios: 16:9, 9:16, and 1:1.
- Keep an editable timeline so operators can adjust zoom depth, timing, cuts,
  captions, and redactions.

## Voice And Audio

Voice should be a separate capability track, not a recorder prerequisite:

- Voice input can become another operator input mode for prompts and
  corrections.
- TTS can generate agent narration from step summaries or an operator script.
- Microphone audio can be recorded for human narration.
- Voiceover edits should become timeline artifacts, not opaque media-only
  changes.

## External Editor Bridge

DaVinci Resolve, Premiere, or other video editors should be integration
targets, not the core implementation path.

Preferred bridge:

- Export video, audio, captions, markers, and cut/zoom metadata in standard
  formats where practical.
- Use official scripting/plugin APIs for editor-specific workflows when they
  exist.
- Treat `computer_*` control of a video editor as an optional assisted workflow,
  not the primary rendering engine.

## Security And Governance

- Recording must require explicit operator/project policy.
- Raw captures, audio, and exports are sensitive artifacts with bounded
  retention.
- Redaction should happen before export when metadata marks fields or regions
  as sensitive.
- The recorder must preserve audit evidence for what was captured, edited, and
  exported.
- Browser/computer automation authority remains in runtime providers; the
  recorder observes and renders evidence.

## Implementation Slices

1. Capture manifest: define shared contracts for raw capture, event, artifact,
   edit, export, and replay tracks.
2. Browser raw capture proof: record a governed Playwright browser session and
   correlate tool events with timestamps.
3. Transcript capture gallery: make screenshot evidence inspectable beside
   tool calls before video export depends on it.
4. Basic renderer: export a video with cursor highlight, captions, and
   click-based zooms from a browser run.
5. Computer capture proof: capture a governed local app/window session on
   Windows with policy checks.
6. Timeline editor: expose zoom/cut/caption/redaction adjustments in GUI.
7. Voice track: add voice input, TTS narration, and microphone capture as
   separate governed tracks.
8. External editor export: emit markers/captions/project metadata for
   professional editing tools.

## Open Questions

- Should recording be per-turn opt-in, per-goal opt-in, or a project policy?
- What capture backend should be used first on Windows for desktop/app video?
- Should generated videos be deterministic enough for regression comparison,
  or optimized only for human showcase quality?
- What redaction model is required before recording user desktops by default?
- Which export format should carry edit metadata across surfaces and external
  editors?
