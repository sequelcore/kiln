projection repair. This control can support a bounded internal decision about a
later preregistered optimization. Quality, authority, privacy, safety, and
terminal truth gate efficiency claims. Collection alone grants no promotion,
release, or cross-harness claim.

`repository_read_only`, `bounded_implementation`, `tool_result_heavy`,

produce 33 scheduled rows. One infrastructure-invalid retry per cell permits

## Preregistered enforcement and oracles

Each attempt has a hard allocation of eight physical provider requests. An
eight-turn conversation receives one request per turn and carries remaining
wall-time and input allowance into subsequent turns. Internal parent/child work
uses the ordinary shared Runtime request envelope. The 180-second trial time
includes the conversation sequence. Input 500,000, output 50,000, 32 tool calls,
and one child are observed tripwires; they are not strict transport-level token,
tool, or child ceilings. No new Runtime budget owner is introduced for this
benchmark. Exhaustion, failed turns, or uncertain continuation evidence stop
further conversation dispatch.

Before each dispatch, the private report reserves that attempt's full request
allocation. Completed turns checkpoint observed evidence. A command crash,
missing physical evidence, uncertain child settlement, or post-dispatch identity
drift halts the cohort with a conservative reservation. No retry is permitted
while execution settlement remains unknown. Timed-out, cancelled, stale, and
recovered child lifecycle records do not establish physical settlement.

Task success and trial validity remain separate:

- Exact and conversation answers must satisfy their declared no-tool contract.
- Repository answers need the required terms, citations, successful targeted
  read evidence, and no workspace change; partial source reads are permitted.
- Shards require eight complete singular reads and a host-verified checksum.
  A frozen random seed determines their contents. The model-visible manifest
  describes the format without revealing the checksum.
- Bounded implementation uses a disposable fixture and the dedicated
  `kiln-bounded-implementation` profile. The dataset owns its sole solver prompt;
  no delegation, pre-completed milestones, or model-reported test result is scored.
  Core owns the verification contract and acceptance rule. CLI owns execution.
- Managed work requires the declared child count, read-only authority, route,
  handoff, and complete transport evidence. A terminal lifecycle label alone
  cannot pass settlement.

Canonical internal benchmark invalids remain invalid attempts. Matching `k=1`
consistency evidence and each task-specific oracle must both pass for success.
Unsuccessful terminal sessions fail even when their error string is empty.

## Identity and retained evidence

Freeze requires committed clean executable source and tracked task inputs.
The freezer cleans and force-builds the root compilation package set, then
binds exact source, input, compiled artifact, protocol, configuration, schedule,
toolchain, hardware, route, and account-policy identities. A tool projection
**recipe** digest binds source/configuration/task declarations; it is not a
claim to have hashed an observed provider schema payload. Actual content-free
schema size/count observations remain separate evidence.

The selected target's canonical account policy owns the account allowlist.
Each account must have fresh authoritative Plus eligibility for that provider
and target at freeze and execution admission. The recorded local freeze window
is not a provider TTL; execution rechecks canonical eligibility. Fallback and
MCP remain disabled and concurrency is one. CLI runs pass `--disable-mcp`;
internal benchmark fixtures admit no canonical external MCP server configuration. Source, compiled artifacts,
configuration, and hardware are rechecked before and after each attempt.

Cold means a fresh session, not a guaranteed provider cache miss. Immediate
warm trials must preserve the observed paired cache partition and child
lineage. Parent and child physical request identities contribute to totals;
unknown usage remains unknown. Tool-call counts follow the parent transcript
projection and are not a claim of complete child-internal tool accounting.

Reports retain only the bounded content-free projection and oracle reason
codes. Raw answers, prompts, tool arguments/results, and invocation records
remain ephemeral to scoring or under existing private Runtime ownership.
Reports bind the frozen manifest and schedule, retain invalid-only cells as
incomplete, detect retry/denominator errors, and invalidate observed request
overruns. Unknown reservations retain observed lower bounds without double
counting. Initial files use exclusive creation; checkpoints replace a private
pending file. An interrupted checkpoint cannot justify restarting the cohort
without reconciling prior execution.

## Bounded implementation verifier revision 2

The current pending protocol replaces the failed coding control's shell-test
requirement. The candidate implements a synchronous, import-free TypeScript
function with exactly the named export. The evaluator checks eight committed
input/result cases, including required errors. It rejects out-of-scope changes
before execution and checks the source and fixture identities again afterward.
The obsolete Bun test-command fixture and duplicate protocol prompt are removed.
Old frozen manifests and reports retain their original identities.

The verifier uses the same container process owner as backend verification, with
a digest-pinned Node image, no network, read-only filesystem and candidate-only
mount, non-root execution, dropped capabilities, and resource limits. Docker and
the pinned runtime are checked before freeze and before bounded model dispatch.
Unavailable verification infrastructure cannot become a successful trial or
trigger an unsandboxed fallback.

Each case uses a fresh VM context with no process, console, imports, or runtime
code generation. Module evaluation, function invocation and error-message access
have timeouts. Only bounded primitive results cross to the trusted wrapper;
expected results remain outside the container. Candidate stdout, fake test
summaries, and early process exits cannot supply completion evidence. This is a
bounded behavioral oracle for this fixture, not a general TypeScript sandbox:
[Node explicitly does not designate `vm` as a security mechanism](https://nodejs.org/api/vm.html).
Docker contains effects; passing these finite cases does not prove correctness
for every input or establish a general adversarial execution guarantee.

The pending collection ceiling is 116 requests: 532 previously observed plus
17 conservatively reserved plus 116 remaining equals the approved total of 665.
The protocol binds verifier revision 2 and its image digest; another live run
requires a new clean source freeze and its ordinary scoped file admission.
