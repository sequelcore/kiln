# Roadmap 08 Slice 1 Closure Plan

## Objective

Close Roadmap 08 Slice 1 after commits `380a36e1`, `094c9877`, and
`dafcf762` by proving that lifecycle attribution reconciles under replay,
does not alter provider requests or task outcomes, and exposes equivalent
evidence or explicit capability gaps across direct-provider and harness
routes. Finish with reproducible closure evidence, residual risk, and canonical
documentation.

## Non-Goals

- No routing, context-admission, prompt, tool-schema, or provider-request
  behavior changes.
- No cache-topology or token-reduction work from later Roadmap 08 slices.
- No inferred semantic precision from provider aggregate usage.
- No benchmark-only runtime path, public performance claim, or provider-live
  test in the required deterministic gate.
- No second context-audit or cost-accounting owner.

## Governing Attribution Decision

Provider-reported aggregate usage remains authoritative for billed input,
output, cache-read, and cache-write totals. Canonical request and
`ContextGovernor` audit evidence may contribute source allocations, but those
allocations remain `estimated` unless the provider itself reports the same
semantic boundary. A provider total that cannot be reconciled to observable
semantic sources remains an `unknown` remainder. Do not proportionally spread
aggregate input across control instructions, procedural context, memory,
transcript, tool schemas, or evidence merely to make the source table appear
complete.

Consequences:

- reconciliation completeness means every provider token is represented by a
  record, including explicit `unknown`; it does not mean every token has a
  fabricated semantic source;
- provider token classes and costs must reconcile exactly (cost within the
  existing floating-point tolerance), while estimated semantic allocations
  must never exceed their provider class total;
- direct-provider and harness routes may differ in source granularity, but the
  difference must be represented as a typed capability gap and benchmark
  limitation rather than silently normalized away;
- replay must reproduce the recorded ledger from canonical events and evidence,
  not retokenize current prompt text or call a provider.

## Slice 1 Exit Criteria

- Every provider-reported token and cost reconciles to a lifecycle record,
  including explicit unknown records where semantic evidence is unavailable.
- Canonical replay reproduces ledger identity, totals, quality labels,
  allocations, unknown remainder, and summary without provider access.
- Attribution-on versus unknown-only comparison proves identical provider
  requests and task outcomes.
- Direct-provider and harness routes expose the same normalized evidence
  obligations; every unavailable field has a typed capability gap.
- The committed closure benchmark is deterministic, runs through canonical
  contracts, and reports reconciliation, replay, cache token classes, unknown
  attribution, and limitations independently.
- Core, runtime, and CLI focused/full tests, repository typecheck, build,
  coverage, DDD validation, quality review, and adversarial review pass.
- Roadmap and architecture docs identify evidence artifact paths and state the
  residual risk below.

## Residual Risk To Publish At Closure

- Provider aggregate input usage generally cannot identify semantic source
  boundaries; those tokens remain partly or wholly `unknown` even when billed
  totals reconcile exactly.
- Runtime token estimates may differ from provider tokenization because of
  provider-native wrappers, tool serialization, hidden control material, and
  cache accounting.
- Deterministic fixture parity proves Kiln contract behavior, not byte-identical
  behavior across nondeterministic live providers or harness versions.
- Cost allocation across mixed token classes remains estimated unless the
  provider reports class-specific cost.
- Optional live evidence can expose additional provider limitations but cannot
  replace the deterministic committed closure benchmark.
