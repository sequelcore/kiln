# Kiln 3.0.0-beta.1 Candidate

Status: prerelease candidate; not published.

Target: `3.0.0-beta.1`.

Prepared: 2026-07-17.

Kiln `2.1.0` remains the supported public package line. Do not use this
candidate note as registry, tag, or installation evidence.

## Candidate Scope

- Governed managed-agent execution with background and parallel lifecycle
  evidence, bounded result resources, recovery, dependency-aware orchestration,
  and heterogeneous agent teams.
- Provider-neutral route eligibility and trusted-execution evidence across
  direct-provider and native-harness paths.
- Canonical action-effect authority and fail-closed admission for tool
  execution.
- Shared operator workspace, target-aware resource inspection, and managed
  execution evidence across CLI, GUI, and TUI.
- GUI execution continuity for live and restored sessions, including canonical
  activity ownership, structured tool output, and long-thread navigation.
- Deterministic CLI output plus provider-neutral benchmark, efficiency, cost,
  and verification evidence.
- Governed resolution of vendored `rg`, `fd`, and `jq` developer tools.

The candidate scope may still shrink before publication. The historical
`2.1.0` record is intentionally unchanged by these post-release changes.

## Managed Invocation Routing Delivery

Status: delivered and independently reviewed on 2026-08-11.

- Runtime owns one user-scoped SQLite serialization domain for managed economic
  commitment and shared Model Gateway/managed-job account capacity, affinity,
  dispatch fencing, settlement, recovery, and reconciliation. Economic
  commitments remain project-namespaced, and managed jobs do not depend on a
  running Model Gateway process.
- Managed status, result, history, replay, CLI, GUI, TUI, SDK, and MCP surfaces
  consume canonical sanitized lifecycle evidence without reconstructing route,
  account, or approval policy locally.
- Structured managed writes require one exact, expiring, single-use Runtime
  approval receipt consumed after economic commitment and before the dispatch
  fence. Missing, stale, revoked, broadened, replayed, or foreign evidence fails
  closed before provider effect.
- Portable SQLite, multiprocess, recovery, projection, and approval fixtures
  passed with workspace typecheck and the dependency-ordered build. Bounded
  OpenCode Go read-only and disposable approved-write probes confirmed exact
  route binding, provider execution, settlement, lease release, and replay.
- Delivery and review evidence is recorded in GitHub issues
  [#34](https://github.com/sequelcore/kiln/issues/34),
  [#39](https://github.com/sequelcore/kiln/issues/39), and
  [#67](https://github.com/sequelcore/kiln/issues/67). The authority is
  Kiln-local; it does not claim provider-global quota or concurrency control.

## Release Blockers

- Configure npm trusted publishing for the canonical GitHub workflow and every
  package in the release cohort. Token-based publication is not an accepted
  fallback.
- Pass the canonical GitHub workflow, including Linux, Windows, and macOS smoke
  validation, from the exact committed candidate.
- Review the final package contents, provenance, changelog, release note, and
  registry state before pushing the release tag.

## Candidate Verification

Run from a clean checkout of the exact candidate commit:

```bash
bun install --frozen-lockfile
bun run typecheck
bun run test
bun run build
```

Release bundle, smoke, and registry verification must follow the canonical
[release runbook](../operations/release.md).

Preparation evidence on 2026-07-17:

- `bun install --frozen-lockfile`, `bun run typecheck`, `bun run test`, and
  `bun run build` passed from the candidate worktree.
- `bun run test:scripts`: 27 deterministic script and release-contract tests
  passed.
- `bun run test:startup-profile`: the Chromium-backed GUI startup gate passed.
- `bun run release:validate --ref v3.0.0-beta.1`: the canonical release
  contract accepted a 13-package cohort and selected the npm `beta` dist-tag.
- `bun run release:pack --ref v3.0.0-beta.1`: produced the complete 13-tarball
  bundle with legal-file and integrity checks.
- `bun run release:smoke`: installed the 10 Windows-x64-compatible packages,
  verified all 13 bundle integrities, imported the public surfaces, exercised
  the CLI and vendored tools, and started the packaged GUI through readiness.
- The complete Chromium parity suite passed (18 tests). A production GUI turn
  through `OpenCode Go / kimi-k3` executed one real read-only tool call,
  reached a terminal response without residual activity, emitted no browser
  console errors, and restored the same tool and response evidence after a
  reload.
- After operator reauthentication, the same production GUI lifecycle passed
  through the intended `Codex OAuth / gpt-5.6-luna` route: one real read-only
  tool call, terminal response, no residual activity or browser console errors,
  and identical restored evidence after reload.
- An ephemeral CLI turn through the same Codex OAuth route and `read_only`
  authority executed the real `read` tool and returned the expected repository
  package-manager value, confirming that the direct-provider path is not
  coupled to GUI session state.

This is local candidate evidence only. Cross-platform workflow smoke, operator
validation of the remaining long-turn and interruption scenarios, trusted
publishing, provenance, and registry verification remain authoritative.
